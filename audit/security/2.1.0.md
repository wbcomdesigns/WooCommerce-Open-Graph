# Security review - 2.1.0

Scope: `git diff 2.0.4..release/2.1.0` (15 files). Reviewer: independent read-only pass, then fixes verified at runtime on wbcom-free.

Result: Critical 0, High 0. Medium 1 and Low 2 found and fixed before tagging.

| Severity | Finding | Fix |
|---|---|---|
| Medium | `[wog_social_share id=""]` loaded any product status, so an Author could publish a post that exposed a draft, private or password-protected product's title, slug, description, price and image in the share links. | Shortcode renders nothing unless the product (or a variation's parent) is `publish` and not password-protected. Verified: draft and protected return 0 bytes, published renders. |
| Low | Rejected X username echoed raw into `add_settings_error` (core prints the message unescaped). Already `sanitize_text_field`ed and admin-only. | `esc_html()` on the value. |
| Low | A nested array in `social_profiles` (crafted POST or import) fatals `trim()` on PHP 8. | Non-string entries dropped before trimming. |
| Hardening (pre-existing) | JSON-LD encoded without `JSON_HEX_TAG`, so a `</script>` in product text from an `unfiltered_html` user could close the tag. | `JSON_HEX_TAG | JSON_HEX_AMP` added; output re-parsed as valid JSON. |

Checked and safe: single settings sanitizer for save and import, admin field escaping, schema `logo`/`sameAs` (`esc_url_raw`), `uninstall.php` (guarded, prepared `esc_like` delete, opt-in data removal by exact keys), sitemap AJAX (nonce + `manage_woocommerce`, fixed URL), share link escaping, meta box save (nonce + `edit_post`), migration guard.

Known, not changed in 2.1.0:
- Settings menu uses `manage_woocommerce` but `options.php` saves need `manage_options`, so Shop Managers can view but not save. Policy decision, left as is.
- `class-wog-sitemap.php` cache cleanup uses an unescaped `LIKE '_transient_wog_%'`; cosmetic over-match.
- `wog_track_share` is open to guests; it only fires an action with sanitized values and stores nothing.
- Uninstall cleans the current site only on multisite.

## Independent QA follow-ups fixed before tagging

- Social Profiles accepted non-URLs (`not a url` became `http://not%20a%20url` in `sameAs`). Now only valid http(s) URLs are kept.
- `migrate_old_settings()` overwrote current values with legacy ones. It now fills only keys still at their default.
